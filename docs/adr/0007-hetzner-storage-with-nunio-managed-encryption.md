# Hetzner Object Storage with nunio-managed encryption

Uploaded Sources are stored in Hetzner Object Storage in `fsn1`, chosen because Hetzner's DPA limits processing to the EU/EEA, with no US parent. Hetzner does not encrypt objects at rest by default; its TOMs make encryption at rest the customer's responsibility, and SSE-C is the only server-side option. nunio therefore manages encryption itself:

- Each Source gets its own SSE-C key, generated by the API and stored in Postgres wrapped by a master key.
- Browser uploads and downloads use presigned URLs plus that Source's SSE-C headers via `fetch()`. Only the authorized owner's browser receives the key. The parser receives a presigned URL and the single file's key, never a master key.
- Two buckets: `quarantine` (browser upload target, unversioned, objects expire after 7 days) and `sources` (versioned, noncurrent versions expire after 30 days). Only the worker promotes a file from `quarantine` to `sources`. No bucket is public.
- Deleting a Source's key renders every stored copy unreadable, including noncurrent versions. Derived chunk text, summaries, and caches in Postgres are encrypted under the same key (see [knowledge-retrieval.md](../design/knowledge-retrieval.md)). Database backups still hold the wrapped key until Neon's point-in-time recovery window ends, so that window is configured to at most 30 days. The documented promise: a deleted Source is gone from nunio immediately and purged from all backups within 30 days.

Master keys (this one and the Temporal payload key) are platform secrets in Vercel and Render. They are separate per purpose and environment, and carry a version ID recorded with everything they encrypt, so keys can be rotated incrementally. Rotation and compromised-key procedures are documented before the pilot.

**Gate:** before building the upload flow, a compatibility spike must confirm on Hetzner:
- presigned PUT with SSE-C headers and a signed Content-Length;
- CORS allowing the SSE-C headers;
- CopyObject between buckets with SSE-C;
- noncurrent-version expiry.

If any of these fail, fall back to AWS S3 `eu-central-1`: default encryption, size-limited presigned POST, and the same two-bucket layout.

## Considered Options

- **AWS S3 eu-central-1**: encrypted by default with documented size-limited POST, but US-parented. Kept as the fallback.
- **Cloudflare R2 (EU jurisdiction)**: free egress and final deletes, but no presigned POST, presigning on the EU endpoint is unverified, and some metadata is processed in the US.
- **Vercel Blob / Neon Object Storage**: rejected; the CDN cache location is unstated, and soft-deleted objects have no documented purge.
