# AI model providers: EU processing, retention, and AI SDK support

Research date: 2026-10-29. Inputs: [product brief](../product-brief.md) ("Security, privacy, and reliability", "Commercial and model configuration"), [ADR-0008](../adr/0008-meaning-of-eu-hosting.md), [ADR-0003](../adr/0003-stack-and-runtimes.md), [ADR-0004](../adr/0004-temporal-cloud-for-durable-execution.md), [ADR-0009](../adr/0009-separate-parser-service.md), [durable AI note](durable-ai.md). Facts come from official provider docs, privacy/trust pages, DPAs, model cards, and AI SDK provider docs read on this date. Nothing was signed up for, installed, or called. Selections below are **proposals**. Model names are the ones the providers' docs list today.

## Finding and recommendation

**Verified, in short:**

- **Anthropic API direct cannot keep inference in the EU.** `inference_geo` accepts only `"global"` (default) and `"us"`, and workspace geo (data at rest) is `"us"` only (A1). That fails ADR-0008's "compute stays in the EU" rule. The same applies to "Claude Platform on AWS" and "Claude Models on Google Cloud (Anthropic managed)", where Anthropic is the processor (A1). Claude in Microsoft Foundry offers only a US Data Zone (A1).
- **Claude is EU-processable through the cloud providers:** Bedrock's `eu.anthropic.*` geo profiles route from `eu-central-1` only to EU Regions (B2–B4). Vertex AI's `eu` multi-region keeps ML processing in EU member states (V1, V3). In both cases the cloud provider, not Anthropic, is the processor (A2).
- **Every candidate except Anthropic direct has an EU-enforceable path:** Bedrock EU geo, Vertex `eu`, OpenAI `eu.api.openai.com` (needs sales approval plus ZDR or Modified Abuse Monitoring), Azure Data Zone EU, and Mistral (EU by default).
- **None of them trains on API customer data by default.** Mistral is the exception that needs action: its help centre says opting out is a toggle (M3), and its DPA allows training "unless Customer is or has opted-out" (M2).
- **Zero retention is easiest on Bedrock.** You set it yourself per Region with `data_retention_mode: none`, and an SCP can enforce it (B5). Elsewhere it is approval-gated: Anthropic (sales), OpenAI (approval), Azure (modified abuse monitoring application), Mistral (request, pay-as-you-go, stateless endpoints only).
- **Covered Models (Claude Fable 5/5.1, Mythos 5/5.1) require 30-day retention everywhere.** On Bedrock, Fable also needs the `aws_review` human-review mode (A2, B5, B6). Exclude them from the pilot allowlist.
- **AI SDK has an official package for every path.** These are `@ai-sdk/amazon-bedrock` (plus `/anthropic`), `@ai-sdk/google-vertex` (plus `/anthropic`), `@ai-sdk/openai`, `@ai-sdk/azure`, `@ai-sdk/mistral`, and `@ai-sdk/anthropic` (S1–S5).

**Proposed shortlist (details in the last section):** primary is Claude on **Amazon Bedrock, EU geo profile, source Region `eu-central-1`**, through `bedrockAnthropic`. Fallback is **Mistral La Plateforme** (EU default endpoint, ZDR requested, training opt-out set). Embeddings run on **Bedrock in the EU**: Cohere Embed v4 via `eu.` geo, or Titan Text Embeddings V2 in-Region Frankfurt, decided by a German retrieval eval. Keep Vertex AI `eu` Claude as the documented alternative if Bedrock's feature gaps bite.

## Workload fit

- **Tool-using agents.** Claude on Bedrock supports client tools. On Opus/Sonnet 5.5, `tool_choice` is limited to `auto`/`none` (B2, B3), so design agents that never need a forced tool call. Use `structuredOutputMode: 'outputFormat'`, not `jsonTool`, which forces a tool (S1, S3).
- **Extraction of Obligations/Facts.** Native structured outputs exist on Bedrock Claude 5.5 (B2–B4) and Mistral (S5). Anthropic structured-output schemas are cached ≤24 h (A2), so keep personal data out of schema text.
- **PDFs and scans: is vision/OCR needed?** Yes, for scanned syllabi. The ADR-0009 parser gives text for born-digital PDFs only. Options: (a) send page images to Claude, since image input is a ✓ modality on Bedrock (B2), or (b) Mistral OCR 4.1, which is EU-hosted and ZDR-eligible as a stateless endpoint (M3, M4). Bedrock PDF document input through AI SDK is documented only "on specific models" (S1), so verify it for Claude 5.5. The parser holds no secrets (ADR-0009), so any OCR API call must come from the worker, not the parser.
- **Batch.** Bedrock Claude 5.5 cards show no Batch tier (B2–B4). Anthropic Batch is 29-day retention and not ZDR (A2). OpenAI and Mistral batches are not ZDR (O1, M3). Plan without batch for student content.
- **German.** No provider page reviewed gives German-specific generation or retrieval figures for these models.

## Embeddings and German retrieval evidence

- **EU-processable options:** Cohere Embed v4 (`eu.` geo) and Titan Text Embeddings V2 (in-Region Frankfurt) on Bedrock (E1). Mistral Embed (EU, ZDR-eligible; M3, M4). `gemini-embedding-001/2` on Vertex `eu` (V2). OpenAI `text-embedding-3-*` with EU residency (O1, Z3).
- **German evidence is weak everywhere.** Titan's service card says V2 was trained on 112 languages, German among them, but "internal testing has been most extensive for English". It reports only aggregate MTEB scores: 0.60 overall and 0.51 retrieval nDCG@10 (E1 service card, "Natural Languages", "Robustness"). Cohere's docs list German (`de`) for "our multilingual embed model" but don't tie that list to v4 or give multilingual retrieval benchmarks ([Cohere Embed docs](https://docs.cohere.com/docs/cohere-embed)). Mistral Embed dates from v23.12 (M4). **No primary source with German retrieval results was found**, so nunio must measure.
- **Proposal:** keep embeddings on the primary processor (Bedrock EU) so retrieval adds no DPA. Choose between Cohere Embed v4 and Titan V2 with a small German/English syllabus retrieval eval. Re-embedding is required to switch, so record the model ID and dimensions per vector row.

## Proposed implications for nunio

1. **Provider registry (proposal).** Register only EU-pinned model IDs in `customProvider`/`createProviderRegistry` ([durable-ai.md](durable-ai.md)): `eu.anthropic.claude-{haiku,sonnet,opus}-5-5` via `bedrockAnthropic` with `region: 'eu-central-1'`, plus Mistral models. Never register `global.*`, `us.*`, Anthropic direct, or Covered Models. "Data-handling differences visible" (brief) then reduces to a per-model label: EU Region set, retention mode, provider.
2. **AWS account guardrails (proposal).** Use a dedicated AWS account and set the Bedrock data retention mode to `none` in `eu-central-1`, with an SCP that denies other modes (B5). Deny `bedrock:InvokeModel*` on `global.*` profiles and in non-EU Regions. Disable or EU-pin invocation logging.
3. **Model routing defaults (proposal).** Haiku 5.5 for extraction and classification, Sonnet 5.5 for agents, explanations, and feedback, Opus 5.5 for hard planning. Validate with evals.
4. **Fallback (proposal).** Mistral is a different model family, so failover needs its own prompt and eval suite. Treat it as a degraded mode, not a transparent swap. Alternative: Vertex `eu` Claude keeps prompts identical but adds Google as a third AI processor.
5. **Secrets.** Bedrock credentials (IAM role or `AWS_BEARER_TOKEN_BEDROCK`) and the Mistral key live in the worker (Render Frankfurt) and API (Vercel `fra1`) only, never in the parser.

**What the pre-pilot DPA review must check specifically:**

- **AWS.** Confirm the DPA and Service Terms cover Bedrock third-party models, including the Anthropic terms on the [third-party models page](https://aws.amazon.com/legal/bedrock/third-party-models/). Confirm whether `data_retention_mode: none` is contractually binding or only a technical setting. Check where `default`-mode abuse data is stored (destination Region, B5). Get the subprocessor list for Bedrock. Check DPF status.
- **AWS cross-Region.** Confirm the `eu.` destination Regions (Stockholm, Milan, Spain, Ireland, Paris, Frankfurt) are acceptable. All are EU, and London and Zurich are excluded only because nunio uses `eu-central-1` as the source.
- **Mistral.** Get the default API retention period and the actual subprocessor list, including which features transfer outside the EU (M1). Get written confirmation of the training opt-out and ZDR approval. Note the DPA's French-law governance.
- **All AI processors.** Check that "no training on student content" is in contract, not only in docs. Check flagged-content and legal-hold retention (e.g. Anthropic ≤2 years, A2; the equivalent on Bedrock). Check breach notification and deletion on termination (Mistral §10.1: 30 days). Check that students' personal data in prompts is covered as processor data.
- **If Vertex or Azure are added later.** Google CDPA SCC section and MaaS (Claude) retention. For Azure, whether the EU Data Zone's possible CH/NO processing is acceptable (Z1).

## Verification to carry into the plan

- From `eu-central-1`, run `aws bedrock get-inference-profile` for each `eu.anthropic.*` and `eu.cohere.*` ID. Record the destination ARNs and fail CI if a non-EU Region appears (B1).
- `PUT /data-retention` with `none` in `eu-central-1`, then `GET` it. Confirm a Fable request is rejected and that Sonnet 5.5 works (B5).
- Test an SCP or IAM policy denying `global.*` and non-EU Regions. Confirm requests fail closed.
- AI SDK spike with `bedrockAnthropic`: tool loop with `toolApproval`, `Output` with `structuredOutputMode: 'outputFormat'`, `cachePoint`, image input, and PDF file part on Sonnet/Haiku 5.5. Record anything the Converse path or `tool_choice` limit breaks.
- Mistral: confirm the training toggle is off for the API workspace, request ZDR, and confirm stateless-only use. Run the same extraction eval suite on Large 4 / Medium 3.5.
